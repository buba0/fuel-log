# Repository instructions

Use the terminal for Git and GitHub operations; prefer git and gh.

Before publishing a repository or making it public, make all documentation and examples generic. Audit tracked files and relevant history for private deployment details, internal hostnames and IP addresses, personal account names, infrastructure identifiers, credentials and secrets. Replace deployment-specific values with clearly documented placeholders or reserved example domains. Keep private runbooks and access details outside the repository. Preserve legitimate public project URLs and attribution. Verify the audit before publishing; report historical exposure separately rather than claiming a current-file edit erased history.
